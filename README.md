# Atoms Lab

Atoms Lab 是一个用自然语言生成文档、代码、网页和数据图表的工作台。

## 实现思路与关键取舍

- **按需分工。** Go 服务管理角色、审批与状态，Eino 执行工具。按需派工控制模型调用量。Build 直接实施，Plan 等用户批准后实施。
- **保存进度。** SQLite 在同一事务保存文件、工具结果和检查点，支持中断后续做。单库便于部署和备份，适合当前单节点规模。
- **实测后交付。** 在 gVisor 中验证 Go 编译与测试、脚本输出和网页交互，报告绑定受测文件版本。固定环境便于复现，可用依赖由镜像决定。
- **两级压缩。** 先按规则压缩旧工具记录，仍超请求体上限时再调用模型摘要旧对话。原始记录可查。

## 当前完成程度

- **已实现。** Build / Plan、澄清与审批、后台执行、停止／续做／重做、版本对比与恢复、ZIP 导出。支持文档、Go、JavaScript／TypeScript／Python、网页和 CSV/JSON 分析。
- **已验证。** 真实模型跑通计划审批、脚本输出、版本恢复和数据图表样例。两级压缩已上线，长任务隔离副本通过真实模型续做验收。云端通过网页交互和多语言执行测试。[演示站](https://atoms.linhengyi.xyz/)
- **待验证。** 长任务完整交付、真实模型成功率、并行容量和长期负载尚待评估。多文件 Go 草稿曾编译失败。
- **未实现。** 账号找回、跨设备同步、多实例调度、在线安装依赖、连接外部 API 或数据库、单独发布生成应用。

## 后续扩展与优先级

1. **P0　提高长任务交付率。** 重复跑多文件 Go、Plan 网页和数据分析样例，记录交付率、调用量和失败原因，确定输出截断、编译和恢复问题的修复顺序。
2. **P1　改善失败后的续做。** 集中展示失败步骤、已保存文件和待补检查，再补账号绑定，方便跨设备找回项目。
3. **P2　按需扩容。** 先测单作业模式的等待时间和资源占用，持续出现瓶颈时再引入持久队列和独立执行节点。
