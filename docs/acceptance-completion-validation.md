## 已执行的验证

- `go test ./... -count=1 -timeout 120s`：通过，包含原有 Agent、执行恢复、上下文压缩、校验和二进制产物回归。真实网络连接中断仍标记用量未知；模拟 429、503、401、主备同时失败、预算限制和停止行为。
- `go vet ./...`、`npm run build --prefix web`：通过。实际截图检查过首页及 390px 账号恢复页面，补齐移动端工具栏换行和账号按钮。
- `npm run test:unit --prefix runner`：4 项通过。模板构建验证 3 个应用 × 1440/390 两种宽度的新增、保存、刷新；共享实际平台 SDK。`expect_saved` 每次等待新的修订，不能拿上一次成功冒充本次保存。
- `node scripts/acceptance_completion.cjs`：真实 Go HTTP 服务、独立 SQLite、Chrome；账号注册、换浏览器、正式数据、故障兜底、分享及离线导出均走真实接口。报告目录为 `artifacts/acceptance-completion-2026-11-13T12-03-53-113Z/`。
- 存储测试主动注入 SQLite 更新失败，确认修订号不前进、无成功回执；并发写仅一方成功；同请求重放返回原修订；切换/回退代码版本后旧授权仍失效；不兼容格式仅在确认后备份并重置。
- 一致性备份使用 `deploy/backup.py`，逐表比较原库与备份的全部行，完整性及外键检查通过；旧版回滚被拒绝，当前兼容构建允许。证据在 `artifacts/acceptance-completion-2026-11-13T12-03-53-113Z/backups/verification.json`。这是隔离库演练，没有在生产环境执行回滚。

端到端服务进程被强制终止后，已确认保存的数据恢复；另一次由浏览器代理扣住后端已提交的响应，再终止后端、向页面返回网络失败，重试同一请求仍得到原修订。测试没有覆盖 SQLite 每条内部指令的断电点，也不证明磁盘损坏恢复。

## 真实模型样例

使用本项目 `/etc/atoms-lab/app.env` 的模型配置，凭据始终留在服务器。输出保存在独立 `/opt/atoms_lab/acceptance/completion-20261113-1151/`，没有修改线上项目代码和业务数据，没有重启服务。每次真实发送都记入本项目原有调用账本和分钟额度。

| 样例 | 模型输出与验证 |
| --- | --- |
| 从零生成待办 | 四个源码/契约文件；实际构建后，在 1440/390 浏览器新增、保存、刷新、完成待办、再次刷新，断言通过 |
| 局部迭代 | 仅改变 `index.html` 中新增按钮文字，其他源码与数据契约哈希不变；复测上述交互通过 |
| 已有网页适配 | 选取已有演示网页的隔离副本，保存/恢复演示页码；仅修改 `app.js`、新增契约，原 HTML 和 CSS 字节完全一致；下一页保存后刷新仍在第 2 页，两种宽度通过 |

本地证据在 `artifacts/live-app-completion-20261113/`：请求回执、各样例源码、构建网页、浏览器检查及 `verification.json`。旧样例代码只在隔离副本中适配，待发布/用户选择后再更新原项目。

第一次探测脚本将输出上限设为 8,192，模型全部用于推理、未返回源码；该次不能记为通过，已保留用量回执。随后脚本改为沿用服务器既有 81,920 上限，3 次生成/迭代/适配完成。合计 4 次真实请求、50,981 Token，均有用量回执。最终三个样例使用真实模型输出和正式构建/SDK，但不是本次新版整个 Agent 调度链在生产上的完整重跑。
