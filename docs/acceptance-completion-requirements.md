本次继续使用现有工作台、Go 服务、SQLite 和受限执行器。具体取舍见[技术方案](acceptance-completion-design.md)。本文描述目标，不代表已上线。

## 2 功能要求

### R01 首次进入有成果

- 首页提供 3～5 个标明“预置示例”的成品，至少包含任务看板、阅读清单和计算器。每个示例都有实际页面、真实交互、示例数据和简短说明。
- 看示例不要求登录、不依赖模型。开始试用时创建当前访客自己的副本，操作不能改变公共样例或其他人的副本。
- 示例副本同样保存业务数据；服务重启不能重新灌入种子数据覆盖用户修改。
- 预置内容与即时生成结果明确区分。公共首页不能展示其他访客的私有项目。

### R02 模型不可用仍有可运行结果

- 缺少配置、无额度、错误密钥、限流、上游故障及连接失败都有明确结果，不白屏、不无限等待。
- 正常路径仍根据自由需求调用真实模型。仅在失败时启用有界重试、已配置的备用通道和最终模板降级。
- 降级成果必须能交互、保存和再次打开，明确标注“演示模式”，说明支持的功能；不能把模板当成完成任意自由需求的证据。
- 如果模型已经改写部分文件，保留草稿、检查点和上一成功版本。演示副本与原项目分开；原项目可以继续原任务。
- 用户主动停止、Plan 等待批准和权限拒绝不能触发自动生成来绕过用户决定。备用通道只使用本项目部署方明确配置的服务端凭据。
- 故障演练使用独立实例或测试工作区，不向公网访客提供修改生产 Key 或全站模型配置的入口。

### R03 账号与游客衔接

- 提供注册、登录、退出，同时保留游客体验。首次注册可保留当前游客项目；登录已有账号时，明确选择是否接收本机游客项目。
- 登录后可在其他设备恢复账号下的项目、代码版本和已保存业务数据。游客清除凭据前应看到如何注册保留数据的提示。
- 密码不可明文保存；会话可过期、可撤销；登录接口需防止高频猜测。退出后旧会话不能继续读写私有数据。
- 旧游客工作区及其文件、任务、检查点、调用账本必须保留。账号绑定不能重新获得已消耗的每日额度，也不能打断后台任务。

### R04 生成应用的业务数据持久化

- 业务数据指需要再次使用的内容，例如任务文字、完成状态、阅读记录、已保存表单。菜单展开和尚未提交的输入属于临时界面状态，可以保留在内存。
- 在线工作台中的业务数据由服务端数据库保存。页面只有得到数据库提交成功的确认后才能显示“已保存”。
- 保存失败或响应丢失时显示明确状态，不能静默改成内存保存并宣称成功。用户未提交、未确认保存成功的内容不承诺重启后恢复。
- 刷新预览、关闭并重开浏览器、正常重启或异常终止后端后，已确认保存的数据仍应恢复。账号用户换设备登录后也应看到同一数据。
- 不同用户和项目的数据隔离。同一账号同时打开两个页面时，旧页面不能静默覆盖新保存的数据。
- 代码修改失败、停止生成和代码版本恢复不能清空业务数据。新旧代码不兼容已有数据时，先保留数据并明确拒绝危险写入。
- 生成代码不能获得工作台 Cookie、模型密钥或任意数据库访问权限。自动测试不能污染用户真实业务数据。
- 已有应用不会因为平台更新自动获得持久化能力；需保留旧版本后适配、验证。原来已经丢失的浏览器内存内容无法恢复。

### R05 保留迭代与预览能力

- 保留局部修改、进度、运行中补充要求、停止、继续、版本对比和恢复。
- 生成失败时默认提供上一可用版本入口；查看失败草稿不能伪装为可交付版本。
- 草稿、历史版本和自动检查的试用数据与当前应用正式数据区分；未验证代码不能直接改写正式数据。
- 页面覆盖桌面和手机，保存中、失败、冲突、离线及演示模式均有清楚反馈。

### R06 分享与导出

- 可为选定的成功版本创建、撤销只读分享链接。未登录访客可查看和交互，但不能修改所有者项目或读取其私有业务数据、对话和运行记录。
- 保留源码 ZIP，增加构建后单文件 HTML 导出；HTML 双击能打开、能交互，无需安装依赖。
- 默认导出和分享不包含所有者的业务数据。所有者可另行导出数据 JSON；导入数据须确认目标并检查格式。
- 在线服务端持久化和下载后的本地文件是不同使用环境。离线 HTML 明确说明保存方式，不把浏览器本地缓存描述为跨设备同步或服务端备份。

### R07 交付可复现

- README 补项目定位、技术栈、完整本地启动、服务端配置、无 Key 体验、测试命令和 AI 使用说明。
- 记录实现取舍、实际完成度、边界、故障排查和下一步计划。线上地址、公共仓库及交付提交可互相对应。
- 验收覆盖无痕、国内手机流量、账号换设备、故障演练和持久化重启；没有实际执行的项保持待验收。
- 发布仍使用现有阿里云独立目录、服务和数据卷，保留备份和回滚版本；不改动其他项目服务。

## 3 验收用例

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| C01 | 无 Cookie 打开首页 | 3～5 个成品可见；点开试用无需模型；两个访客的操作互不影响 |
| C02 | 清空或填错模型 Key 后提出网页需求 | 有明确演示提示和可运行预览；能新增业务记录并刷新恢复；不冒充完成原需求 |
| C03 | 分别模拟普通 429、网关 TPM、503、连接失败和额度耗尽 | 重试与等待有上限；备用或模板路径明确；所有实际模型发送照常记账 |
| C04 | 在已有成功版本上触发迭代失败、停止或超时 | 原成功版本和业务数据未被覆盖；保存的草稿可继续；停止不触发模板替换 |
| C05 | 游客创建项目后注册；另一浏览器登录 | 原项目、文件、检查点和业务数据可恢复，原游客凭据不能越权访问 |
| C06 | 登录已有账号并选择接收或暂不接收游客项目 | 两种选择符合提示；接收仅一次，归属及累计配额不被重置 |
| C07 | 同账号两个设备操作，不同账号猜测项目 ID | 同账号可恢复；跨账号读取、写入、导出、预览和事件流均被拒绝 |
| C08 | 登录后退出、重复使用旧 Cookie、连续错误密码 | 旧会话无效；限流有效；数据库、日志和接口不出现明文密码或密钥 |
| C09 | 新增并完成待办，看到已保存后刷新、重开、重启服务 | 内容及完成状态一致，不能通过重新写入默认数据蒙混通过 |
| C10 | 分别在提交前终止、提交后响应前终止、返回成功后终止后端 | 前者不声称保存；后两者可恢复已提交内容，重试同一操作不重复新增 |
| C11 | 双页面用相同旧修订号修改；模拟数据库写失败 | 不静默覆盖；冲突或失败可见；用户可重新加载后决定如何修改 |
| C12 | 切换项目、重载 iframe、恢复代码版本，再发送旧页面写入 | 过期写入被拒绝；兼容版本能读原数据，不兼容版本不清空数据 |
| C13 | 对持久化应用运行桌面和手机交互检查 | 覆盖新增、修改、刷新恢复；测试数据未进入正式业务表 |
| C14 | 打开分享链接并修改试用数据，随后撤销链接 | 所有者数据不变、私有信息不可见，撤销后刷新无法继续访问 |
| C15 | 下载 HTML 并断网双击；导出及导入数据 JSON | HTML 能运行；数据保存范围有说明；不夹带凭据或默认泄露所有者数据 |
| C16 | 新环境按 README 启动；手机流量打开线上地址 | 启动可复现，无 Key 路径可用；国内访问和 390px 界面由实际设备验证 |
| C17 | 从发布前备份迁移，再模拟兼容回滚与服务恢复 | 既有记录、归属和配额保留；不能用旧认证程序重新开放已绑定账号的游客入口 |

C01～C17 是本次计划中的验收，不是通过记录。六维评分没有逐分规则，因此不预先承诺 21/30；先逐条满足硬要求并保留可复跑证据。

## 4 范围边界

本次先支持小型应用的结构化 JSON 业务数据，不加入任意 SQL、外部数据库连接、多人协作编辑、组织权限、支付、OAuth、邮件找回密码或应用独立云托管。具体容量、保存冲突处理及兼容策略由技术方案确定。

服务端已提交数据的重启恢复是本次承诺；磁盘损坏、整机丢失和离线浏览器缓存清除需要备份或导出恢复，不能与正常进程重启混为一谈。现有备份需覆盖新增表并验证恢复，但本次不扩建高可用集群。
